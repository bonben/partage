1. TP 1 : piloter une IP depuis l'espace utilisateur¶

Durée : 40 min. Objectif : atteindre une IP du FPGA sans écrire de code noyau, et voir pourquoi cela ne suffit pas. Les parties 1.1 à 1.4 sont pour tous ; la 1.5 est pour les rapides ; la 1.6 est montrée par le formateur.

1.1 Lire la chaîne de démarrage sur la carte¶

Sur la carte
uname -a
cat /proc/cmdline
mount | grep nfs
cat /proc/iomem

Questions

  • Dans /proc/cmdline, qui a fourni ces arguments au noyau ?
  • Où dit-on au noyau que sa racine est en NFS ?
  • Pourquoi ne voit-on pas le chenillard dans /proc/iomem ?

1.2 Compilation croisée¶

Sur le poste
cd tp1
make hello
file hello
./hello
Sur la carte
cd /home/user/tp/tp1
./hello

Restez dans tp1 des deux côtés jusqu'à la fin de ce TP.

Questions

  • Que répond le poste quand on y lance hello ?
  • Que dit file ?

1.3 Écrire dans les registres sans programmer¶

BusyBox fournit devmem, qui lit ou écrit un mot à une adresse physique. Les registres du chenillard commencent à 0x43C00000 :

Décalage Registre Rôle
+0 mode 0 : motif fixe ; 1 à 3 : rotation vers la gauche ; 4 à 7 : rotation vers la droite
+4 vitesse durée d'un pas, en unités de 10 ms : plus la valeur est grande, plus c'est lent
+8 motif les huit LED en mode 0
Sur la carte
devmem 0x43C00000 32 0       # mode 0 : motif fixe
devmem 0x43C00008 32 0xAA    # les LED affichent 10101010
devmem 0x43C00000 32 1       # mode 1 : quatre LED allumées tournent
devmem 0x43C00004 32 7       # un pas toutes les 80 ms
devmem 0x43C00004 32         # relire la vitesse

Essayez d'autres modes et d'autres vitesses.

Le registre de motif ne sert qu'en mode 0

Dans les autres modes, l'IP part d'un motif qui lui est propre, chargé au moment où l'on écrit le mode.

1.4 Le même accès en C : /dev/mem et mmap¶

Ouvrez le dossier du TP dans VS Code. C'est l'éditeur que tout le monde utilise aujourd'hui : gardez cette fenêtre ouverte, elle servira aussi pour les drivers du TP 2.

Sur le poste
code /srv/nfsroot/arkane/home/user/tp

Dans l'explorateur de fichiers, à gauche, ouvrez tp1/devmem.c.

Ce programme fait la même chose que devmem, en C. L'ouverture de /dev/mem et l'appel à mmap sont déjà écrits ; lisez-les, ce sont les deux lignes vues en cours :

int fd = open("/dev/mem", O_RDWR | O_SYNC);
volatile unsigned int *regs = mmap(NULL, TAILLE, PROT_READ | PROT_WRITE, MAP_SHARED, fd, CHENILLARD_BASE);

Après mmap, regs pointe sur les registres du chenillard : regs[0] est le mode, regs[1] la vitesse, regs[2] le motif.

Il reste deux endroits à compléter, marqués À COMPLÉTER dans le fichier :

  1. la valeur de CHENILLARD_BASE : l'adresse physique du chenillard (voir 1.3) ;
  2. trois affectations : écrire mode dans le registre de mode ; puis valeur dans le registre de motif si le mode vaut 0, dans le registre de vitesse sinon.
Sur le poste
make devmem
Sur la carte
./devmem 0 0xAA     # les LED affichent 10101010
./devmem 1 7        # le chenillard tourne
Indice pour les trois affectations 
regs[0] = mode;
if (mode == 0)
    regs[...] = valeur;   /* registre de motif */
else
    regs[...] = valeur;   /* registre de vitesse */

Questions

  • Que se passe-t-il si l'on écrit directement *(int *)0x43C00000 = 1; dans un programme ?
  • Pourquoi le dernier argument de mmap doit-il être un multiple de 4096 ?

1.5 Pour les rapides : lire les interrupteurs¶

Les huit interrupteurs se lisent dans le registre de données d'un AXI GPIO, à 0x41220000. Le programme tp1/interrupteurs.c scrute les interrupteurs en boucle et règle la vitesse du chenillard en conséquence. Il est écrit, sauf deux lignes marquées À COMPLÉTER : l'adresse des interrupteurs, et l'écriture de la vitesse.

Sur le poste
make interrupteurs
Sur la carte
./interrupteurs      # bougez les interrupteurs ; Ctrl-C pour arrêter

Questions

  • Combien de temps CPU consomme ce programme ? Ouvrez une seconde console (telnet 192.168.74.2 depuis le poste) et lancez top.
  • Comment saurait-il qu'un interrupteur a bougé sans regarder en boucle ?

1.6 Limites (démonstration du formateur)¶

Le programme des interrupteurs est lancé deux fois en même temps, avec des vitesses différentes, puis en utilisateur non root.

À retenir pour le TP 2

Listez ce qui ne va pas avec /dev/mem pour un produit : droits, protection entre programmes, adresses dans le code, interruptions.
